Cm-level BLE Channel Sounding

Passive Entry / Passive Start needs a distance, not a class label. TI CC2745 initiator/reflector firmware plus a Python ranging pipeline: raw HCI I/Q → MUSIC / ToF → robust filters → Kalman. This is the same job as GPS-denied UAV pose: noisy ranging, multipath, timing, fusion.

Pipeline

What I actually owned

  • C firmware on car_node / key_node (SimpleLink F3 / CC2745), CS event timing, disconnect self-reset.
  • Raw hex parser + cross-check against firmware-decoded fields (Phase 1 validation).
  • Algorithm bake-off: SDK distance vs WLR vs MUSIC vs fused proposal; benchmark runner and plots for the Japanese OEM.
  • Walk-speed jump gate (~2.1 m/s) so a static MAE does not cheat a moving key.

Why it belongs on a UAV CV

GPS-denied navigation is ranging + timing + fusion under multipath. BLE Channel Sounding is the same loop at 2.4 GHz instead of a depth camera. I would not claim this is PX4. I would claim I already debug noisy estimators, firmware event timing, and Kalman gates — which is the hard part of VIO into EKF2.
